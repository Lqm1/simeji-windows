# Domain docs

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for domain vocabulary.
- `docs/adr/` for architecture decision records.

## Before exploring

Read the glossary and ADRs relevant to the work.
If these documents do not exist, proceed silently.
Create them through domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, code, and tests.
When a needed term is missing, reconsider the wording or record the gap
for domain-modeling.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain why
the decision should be reconsidered.
