# 製品仕様書

本ドキュメントは、Windows 11 (x64) 向けSimeji日本語入力システム（IME）の製品仕様および要件を定義します。実装の進捗状況および動作検証結果については[検証状況と残課題](status.md)を参照してください。

## 1. 目的とスコープ

### 1.1 開発目的
Android版Simeji 23.6.1の変換コアおよび辞書アセットをWindows 11環境へ移植し、同等の変換精度と豊富な語彙力をPC上で利用可能とすることを目的とします。
Windows環境における操作体系およびUI表示は標準的なMicrosoft IMEに準拠させ、過度な独自UIを排除したシンプルで快適な入力体験を提供します。

### 1.2 対象プラットフォーム
- **対象OS**: Windows 11 (x64)
- **入力機器**: 物理キーボード（JIS / US配列）およびWindows標準タッチキーボード
- **配布方針**: 個人利用およびローカルビルドを前提とし、パブリックなバイナリ配布や公式リリースは行いません。
- **対象外事項**: Android版特有のソフトウェアキーボード画面、フリック入力、スキン着せ替え、画像・スタンプ表示機能などは対象外とします。

## 2. 変換機能要件

### 2.1 ローカル変換
- **入力モード**: ローマ字入力によるかな漢字変換に対応すること。
- **基本操作**: 未確定文字列の入力、文節変換、変換候補の選択、文節の伸縮および移動、確定、取り消し（キャンセル）をオフラインで完結して実行できること。
- **変換コアの整合性**: 独自の変換規則による近似ではなく、Simeji本来のネイティブ変換エンジンおよび同梱辞書データを忠実に実行することを最優先とします。
- **実行方式**: x64環境下でのARMネイティブライブラリの実行には、Unicorn等の組み込みエミュレーターを活用し、安定した変換API呼び出しを実現します。
- **データ永続化**: 入力履歴に基づく変換学習およびユーザー登録辞書は、ユーザープロファイル（`%LOCALAPPDATA%\SimejiWindows`）配下に永続化します。

### 2.2 クラウド変換（超変換）
- **クラウド連携**: Simejiの「クラウド超変換」API（`https://cloud.simeji.me/py`）との通信機能を備え、最新の流行語や口語表現などのクラウド候補を取得できること。
- **オプトイン設計**: プライバシー保護のため初期状態は無効とし、ユーザーの明示的な設定により有効化する仕様とします。
- **耐障害性**: ネットワーク切断や通信タイムアウト時もローカル変換が自動的に継続され、ユーザーの入力を妨げないこと。
- **セキュリティ・プライバシー保護**: パスワード入力欄、PIN入力欄、プライベート指定の入力スコープでは、ホストアプリケーションからの通知に基づき、クラウドへの送信およびローカル学習を自動的に遮断すること。

## 3. UIおよび操作仕様

### 3.1 候補ウィンドウ（Candidate Window）
- **レイアウト**: 標準的なMicrosoft IMEに準拠し、最大9件の番号付き縦並びリスト、明確な選択ハイライト、アクセントカラーインジケーター、ページ切り替えボタンで構成します。操作ガイド（「Tabキーを押して選択します」等）は非表示とし、視認性を高めます。
- **予測候補表示（サジェスト）**: 未確定入力中から非同期に候補を取得・表示し、最初のSpaceキー押下で文節変換候補へスムーズに切り替わります。
- **非同期レンダリング**: 候補の取得処理によってキー入力の応答（タイピングの打鍵感）を阻害しないこと。また、候補ウィンドウの不要な破棄・再生成を排し、画面のちらつきが発生しないインプレース描画を行うこと。
- **システムデザインの統合**: Windowsのライト／ダークテーマ、システムのアクセントカラー、ハイコントラスト設定に追従し、カラー絵文字（DirectWrite）の描画に対応すること。
- **UIレスモードのサポート**: フルスクリーンゲームや独自検索バーなど、アプリケーション側が候補描画を担う場合（TSF UIレスモード）は、内蔵候補ウィンドウの表示を適切に抑制すること。

### 3.2 キーボード操作
- 標準Microsoft IMEと同一のキーバインドを提供し、一般的なWindows日本語入力と違和感のない操作性を実現します。
- **未確定入力時**:
  - `Space`: かな漢字変換を開始
  - `Enter`: 未確定文字列をそのまま確定
  - `Esc`: 入力の取り消し（未確定文字列を消去）
  - `Backspace` / `Delete`: 前後の文字削除
  - `←` `→` / `Home` `End`: 未確定文字列内のカーソル移動
  - `Tab` / `↓`: 表示中の予測候補へフォーカスを移動
- **変換中**:
  - `Space` / `↓`: 次の候補を選択
  - `Shift+Space` / `↑`: 前の候補を選択
  - `Shift+↓` / `Shift+↑`: 候補一覧の次／前ページへ移動
  - `1`～`9`: 該当番号の候補を選択して即時確定
  - `←` `→`: 注目文節の移動
  - `Shift+←` `Shift+→`: 注目文節の伸縮（区切りの変更）
  - `Esc` / `Backspace`: 変換を取り消し、未確定の読み入力に戻る
  - `Enter` / 新規文字入力: 選択候補を確定
- **末尾「n」の自動補完**: 入力末尾の「n」は、変換開始、確定、カーソル移動時に自動的に「ん」へ補完すること。

## 4. プロジェクト管理および品質方針

### 4.1 リポジトリ管理基準
- リポジトリ内には、ビルド、テスト、実行、ドキュメントに必要な正規のソースコードと製品アセットのみを管理します。
- 一時的なリバースエンジニアリング成果物、展開物、作業ログ等はリポジトリおよびプロジェクトディレクトリから除外します。

### 4.2 実装品質基準
- Rustコードは公式のRust BookおよびAPIガイドラインに準拠し、適切なモジュール分割、エラーハンドリング（`Result`型）、テスト駆動開発を徹底します。
- Windows APIおよびTSFとの統合においては、Microsoft公式のText Services Framework仕様に厳密に準拠します。
