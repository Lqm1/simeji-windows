## 標準的なインストールと通信

Windows IMEとして標準的な形にそろえた。プログラムは `%ProgramFiles%\SimejiWindows`、COM登録は `HKLM`、ユーザーデータは `%LOCALAPPDATA%\SimejiWindows` の `settings.json`・`user-dictionary.json`・`Learning\`・`Cache\`、パイプはユーザーとセッションごとの名前と所有者付きの権限になった（[現在の構成](architecture.md)）。

- 確認済み: 書式・lint・全テスト、パッケージ作成と `simeji-setup verify`、パッケージのワーカーを新しいパイプで起動し、Ping・変換・ユーザー辞書登録・ランチャーの重複起動防止・データ配置を確認した。
- 未確認: 管理者権限での `install.ps1`・`uninstall.ps1`、`HKLM` への登録と `InstallLayoutOrTip`、アプリでの入力、AppContainerアプリからの接続。
- 以前の版とは互換性がない。旧版の `%LOCALAPPDATA%\SimejiWindows\Versions` と `UserData` は新しい版では使わない。旧版をアンインストールしてから導入し、学習データを引き継ぐ場合は旧 `UserData` 内の学習ファイルを `Learning\` へ、`user-dictionary.json` を `%LOCALAPPDATA%\SimejiWindows` へ移す。

## 発生した問題と現在の理解

### IMEを選択しても元に戻る

IMEの一覧登録は存在したが、利用ユーザーからCOM経由で本体を作成すると `0x80040154`（クラス未登録）になった。利用ユーザーのCOM登録を補った後、本体の作成は成功し、利用者から切り替え可能との報告があった。

登録が最初から欠けていたのか、後から失われたのかは未確定。利用者環境だけの破損とも、インストーラーの正常性が確認できたとも判断しない。汎用の診断・修復コマンドの追加案は利用者が不要と判断し、ソース変更を取り消した。

### 切り替え後も英字しか入力できない（解消済みの構成上の原因）

通常権限からワーカーへ接続すると `0x80070005`（アクセス拒否）になった。ワーカーが管理者権限で起動している可能性を案内し、管理者側で停止して通常権限で起動する手順を提示した。その後、利用者から良好に入力できるとの報告があった。接続拒否の観測と、プロセスの権限を直接検証した事実は区別する。

## 次に改善する内容

利用者から次の課題が報告されている。具体的な再現条件や受入基準は、各修正で確認する。

- 一部操作のもたつき。リリースビルドで計測した原因は、Unicornのタイムアウト処理がネイティブ呼び出し1回ごとに約15ms待つことだった。独自の時間制限に置き換え、キー入力ごとの読み変換は約78msから約1ms、確定時の学習は約310msから約25ms、エンジンの起動は約790msから約220msになった。文変換（約120ms）と文節候補（約160ms）は大半がエンジン自体の処理である。
- Backspaceの動作。
- 変換候補画面のUI/UXと細かい操作感。

構成の整理時に、次の現在の挙動をテストで固定した。改善するかどうかは各修正で判断する。

- 変換中のBackspaceは、最後のローマ字を1文字削除して読みの表示へ戻る。
- 変換前の読みの入力中は、矢印キーを入力先アプリへ渡す。
- JISキーボードの「ろ」キー（`\`、`_`）は入力対象のキーに含まれず、入力先アプリへ渡る。

インストール直後の通常ユーザーからの利用も改善対象。新規インストールで同じ登録・権限問題が起きないことは、今回の復旧操作だけでは保証できない。

## 再解析を検討する条件

通常の入力体験の改善では、既存のソースと実機検証を使う。変換候補の欠落、学習の不整合、ネイティブ実行の障害、クラウド通信仕様の変化など、エンジンとの接続仕様を調べる必要がある場合に再解析を検討する。要求の再現が難しいと分かった場合は、仕様に従って利用者へ再相談する。
