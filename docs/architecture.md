# 現在の構成

製品の要求は[製品仕様](specification.md)、確認済みの範囲は[検証状況](status.md)を参照する。この文書は実装の責務と採用理由を説明する。

```text
入力先アプリ
  └─ TSF DLL（crates/ime）
       └─ 名前付きパイプ（crates/transport、crates/protocol）
            └─ simeji-worker
                 ├─ Engine → Unicorn → ARM変換エンジン・辞書
                 ├─ 学習・ユーザー辞書
                 └─ CloudWorker → クラウド通信・キャッシュ
```

## Windows側

`crates/ime` はWindowsに読み込まれるCOM/TSF DLL。キー入力、未確定文字、文節・候補選択、編集セッション、入力スコープ、表示属性、候補ウィンドウを担当する。変換エンジンそのものは保持しない。

同じクレートの `simeji-setup` は登録・解除とDLLの検査、`simeji-launcher` はワーカーの起動を担当する。現在の `verify` はDLLの直接ロードとCOMインターフェースの検査であり、登録済みのIMEをWindowsが有効化して入力できることを保証するものではない。

## 変換ワーカー

`src/bin/simeji-worker.rs` が変換エンジンを保持する。`src/engine.rs` は変換・学習・辞書登録、`src/arm.rs` はARM実行、`src/elf.rs` はライブラリのロード、`src/host.rs` は必要なAndroid実行環境との接続を担当する。

元のエンジンと辞書を使うのは、独自変換による近似を避けるため。ARMライブラリをUnicornで実行することで、Windows x64から利用する。TSF DLLとワーカーを分け、エンジンの実行状態を入力先アプリのプロセスから分離する。ただし、同期要求を待つ間の入力遅延まで防ぐ構成ではない。

`crates/protocol` は変換・学習などの要求と応答の型、`crates/transport` は所有者に制限したローカル名前付きパイプとタイムアウト付きの通信を担当する。

## クラウド

`src/cloud.rs` は有効化設定、HTTP通信、候補の読み取り、キャッシュを扱う。`src/cloud_worker.rs` はバックグラウンド要求と入力更新時の古い結果の排除を担当する。TSF側は読みと応答の対応を確認して候補を追加する。HTTP処理を入力先アプリで実行しない。

## 配置と権限

`scripts/build.ps1` はローカル用パッケージを作る。インストーラーは管理者権限で実行し、製品を `%LOCALAPPDATA%\SimejiWindows\Versions` 以下に配置して登録する。学習・ユーザー辞書・クラウド設定は `UserData` 以下に保存する。

ワーカーは入力先アプリと接続できる通常権限で起動する。インストールに管理者権限が必要なことと、常駐ワーカーを管理者として起動することは別である。

## 変更の境界

候補の見た目、削除・確定・取消、フォーカスや入力モードは主にTSF側で扱う。応答速度や再接続の改善は通信・ワーカーにも及びうる。変換コアを当面維持する方針は、これらの内部実装を固定するという意味ではない。
